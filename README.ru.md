# Crystallized v2.0

Crystallized представляет собой MCP-сервер постоянной памяти для [opencode](https://opencode.ai). Он обеспечивает ИИ-агенту долговременную память между сессиями, формирует эволюционирующую идентичность и гарантирует надёжную первопартийную авторизацию в Anthropic.

Обычные сессии агента начинаются с чистого листа. Crystallized меняет это: система фиксирует сигналы трения, обобщает наблюдения в устойчивые правила и автоматически подмешивает нужный контекст в каждый промпт.

**Версия 2.0 работает без внешних сервисов.** Нет Redis, нет брокеров сообщений и нет фоновых демонов. Вся система опирается на один файл SQLite в режиме WAL и локальные markdown-файлы.

```
+-------------------------------------------------------------------------+
|                            ПРОМПТ ПОЛЬЗОВАТЕЛЯ                          |
+------------------------------------+------------------------------------+
                                     |
                                     v
+-------------------------------------------------------------------------+
| ХУКИ ПЕРЕД ПРОМПТОМ (memory-inject.py + own-voice.py)                   |
| * Подмешивают активные убеждения, факты и причинные выводы             |
| * Добавляют идентичность агента, текущий фокус и наблюдения             |
+------------------------------------+------------------------------------+
                                     |
                                     v
+-------------------------------------------------------------------------+
| ВЫПОЛНЕНИЕ АГЕНТА (opencode + MCP-инструменты)                          |
| * Читает и сохраняет факты, документы и убеждения                       |
| * Запускает субмиллисекундный хук-наблюдатель на каждом инструменте     |
+------------------------------------+------------------------------------+
                                     |
                                     v
+-------------------------------------------------------------------------+
| ПРИЧИННОЕ НАБЛЮДЕНИЕ (observer.py)                                      |
| * Хуки PostToolUse / Stop ловят трение без блокировки выполнения        |
| * Дописывают сырые следы Уровня 0 (L0) в SQLite WAL                    |
+------------------------------------+------------------------------------+
                                     |
                                     v
+-------------------------------------------------------------------------+
| НОЧНАЯ КОНСОЛИДАЦИЯ DREAM (dream.py в 04:00)                            |
| * L0 Следы -> L1 Эпизоды -> L2 Паттерны -> L3 Аксиомы                   |
| * Разрешение би-темпоральных противоречий + степенное затухание памяти  |
+-------------------------------------------------------------------------+
```

## Ключевые возможности

- **Ноль Redis, 100% SQLite WAL**: Один файл базы данных `~/.config/opencode/memory/memory.db`. Мгновенный старт, устойчивость к сбоям, никаких сервисов для обслуживания.
- **Иерархическая причинная память**: Превращает сырые результаты команд (L0) через эпизоды (L1) и повторяющиеся паттерны (L2) в обобщённые принципы и аксиомы (L3).
- **Би-темпоральные убеждения**: Таблица `belief_state` разделяет время валидности утверждения и время его фиксации. Противоречия разрешаются вытеснением старых записей без удаления истории.
- **Субмиллисекундный хук-наблюдатель**: `observer.py` проверяет вывод инструментов по регулярным выражениям с жёстким лимитом по времени, не задерживая ход работы.
- **Ночной движок Dream**: `dream.py` консолидирует опыт каждую ночь, отсекает шум, пересчитывает степенное затухание и формирует готовые принципы.
- **Первопартийная авторизация**: Извлекает реальные OAuth-токены из Claude Desktop на macOS и Windows, обходя сбои веб-авторизации PKCE и лимиты сторонних пулов.

## Архитектура

Crystallized разделяет память на три взаимодополняющих слоя:

| Слой | Движок | Основное назначение |
|---|---|---|
| **Факты и убеждения** | SQLite (WAL) | Мгновенные факты ключ/значение, би-темпоральные убеждения, карта затухания. |
| **Семантический поиск** | ChromaDB | Поиск по смыслу среди текстовых воспоминаний прошлых диалогов. |
| **Структурированные документы** | Файловая система | Архитектурные заметки, чеклисты, файлы идентичности в формате markdown. |

```
~/.config/opencode/
|-- opencode.json                    # Регистрация MCP и конфигурация плагинов
`-- memory/
    |-- memory.db                    # Единая база данных SQLite (режим WAL)
    |-- server.py                    # MCP-сервер инструментов памяти и убеждений
    |-- db.py                        # Схема SQLite, би-темпоральные таблицы, миграции
    |-- volume.py                    # Математика степенного затухания памяти
    |-- observer.py                  # Быстрый хук для событий PostToolUse и Stop
    |-- patterns.py                  # Шаблоны обнаружения ошибок и исправлений
    |-- dream.py                     # Ночная консолидация и синтез правил
    |-- memory-inject.py             # Хук инъекции контекста перед промптом
    |-- own-voice.py                 # Хук инъекции идентичности перед промптом
    |-- chroma_db/                   # Локальное векторное хранилище
    `-- notes/                       # Markdown-документы
        |-- architecture/
        `-- self/
            |-- beliefs.md
            |-- focus.md
            `-- observations.md
```

## Иерархия памяти

Сырой опыт постоянно дистиллируется. Одиночные ошибки шаг за шагом превращаются в правила поведения:

```
[ L3: Аксиома / Принцип ]       "Всегда накатывать миграции до запуска воркеров"
            ^
            | (Обобщение и кластеризация эпизодов)
[ L2: Повторяющийся паттерн ]   "Падение воркера с MissingColumnError при деплое"
            ^
            | (Связка причины и следствия внутри сессии)
[ L1: Эпизод ]                  "Пропущена миграция базы данных при срочном фиксе"
            ^
            | (Хук-наблюдатель фиксирует сигнал трения)
[ L0: Сырое наблюдение ]        "Error: column 'session_id' does not exist in table 'jobs'"
```

1. **L0 (Сырое наблюдение)**: Фиксируется на лету скриптом `observer.py` при вызове хуков `PostToolUse` и `Stop` при падении команды или ручном исправлении.
2. **L1 (Эпизод)**: Последовательность действий, связывающая триггер, попытку исправления и результат в рамках одной сессии.
3. **L2 (Паттерн)**: Повторяющаяся ситуация из нескольких сессий, отражающая типичные ловушки проекта.
4. **L3 (Аксиома)**: Правило высокой уверенности, сохранённое в таблице `belief_state` и синхронизированное в `beliefs.md`.

## Быстрый старт

### Установка

Склонируйте репозиторий и запустите установочный скрипт:

```bash
# Перед запуском полностью закройте Claude Desktop (Cmd+Q на macOS)
git clone https://github.com/enkinvsh/crystallized.git
cd crystallized
./install.sh
opencode
```

Проверить действия скрипта без изменения файлов можно с флагом `--dry-run`:

```bash
./install.sh --dry-run
```

### Что делает install.sh

1. Проверяет наличие `git`, `python3` (3.11+) и `curl`.
2. Устанавливает менеджер пакетов `uv`, если он отсутствует.
3. Скачивает и ставит CLI-утилиту `opencode` при необходимости.
4. Копирует модули памяти в `~/.config/opencode/memory/` и создаёт `.crystallized-manifest`.
5. Устанавливает зависимости в изолированное окружение через `uv sync --frozen`.
6. Инициализирует схему SQLite (`memory.db`) в режиме WAL.
7. Создаёт базовые файлы идентичности (`beliefs.md`, `focus.md`, `observations.md`).
8. Прописывает MCP-сервер памяти в `~/.config/opencode/opencode.json`.
9. Регистрирует хуки в `~/.claude/settings.json`, сохраняя все сторонние хуки.
10. Настраивает ночную задачу (`launchd` на macOS, `cron` на Linux).
11. Извлекает первопартийные токены на macOS.

### Флаги установщика

| Флаг | Назначение |
|---|---|
| `--dry-run` | Выводит планируемые операции без записи на диск. |
| `--no-hooks` | Пропускает регистрацию хуков в `~/.claude/settings.json`. |
| `--no-daemon` | Пропускает установку ночного демона dream. |
| `--offline` | Запрещает сетевые загрузки, требуя локальные бинарники. |
| `--help`, `-h` | Показывает список параметров и завершает работу. |

## Авторизация

При использовании платной подписки Anthropic (Claude Pro или Max) стандартные веб-флоу PKCE в сторонних клиентах часто ломаются. Anthropic проверяет заголовки клиентов и направляет нераспознанные сессии в ограниченный пул либо возвращает ошибку HTTP 429.

Crystallized извлекает токены напрямую из Claude Desktop. Они несут подлинные клиентские идентификаторы. В сочетании с плагином `@thehugeman/opencode-anthropic-auth-community` все запросы opencode принимаются как первопартийные.

```
+---------------------+      +---------------------+      +---------------------+
|   Claude Desktop    | ---> | auth/extract_token  | ---> |   opencode auth     |
| (Зашифровано)       |      | (Keychain / DPAPI)  |      |   (~/.local/share)  |
+---------------------+      +---------------------+      +---------------------+
```

### Извлечение токена на macOS
На macOS данные шифруются через Electron safeStorage (AES-128-CBC) с паролем из системного Keychain:

```bash
# 1. Войдите в аккаунт в Claude.app
# 2. Полностью закройте Claude.app (Cmd+Q)
# 3. Запустите скрипт
python3 auth/extract_token.py
```

### Извлечение токена на Windows
На Windows применяется двухслойное шифрование (мастер-ключ через DPAPI + шифрование AES-256-GCM):

```powershell
# 1. Войдите в аккаунт в Claude Desktop для Windows
# 2. Полностью закройте Claude.exe
# 3. Запустите скрипт
python auth\extract_token.py
```

Подробную инструкцию, разбор ошибок и параметры автоматического запуска смотрите в [Руководстве по авторизации](docs/AUTHENTICATION.md).

## MCP-инструменты

Crystallized предоставляет набор инструментов для агентов и разработчиков:

### Факты и убеждения
- `memory_save_fact(key, value, ttl_days)`: Сохранить факт ключ/значение с опциональным временем жизни.
- `memory_get_fact(key)`: Получить факт по точному ключу с усилением громкости.
- `memory_list_facts(prefix, limit, full)`: Найти факты по префиксу ключа.
- `memory_delete_fact(key)`: Удалить факт.
- `memory_belief_assert(id, subject, predicate, object_val, confidence)`: Утвердить убеждение с атомарным вытеснением старого значения.
- `memory_belief_get_active(subject, predicate)`: Получить текущее активное убеждение.
- `memory_belief_list_active(subject)`: Список активных убеждений по предметной области.

### Семантическая память и документы
- `memory_remember(text, tags)`: Сохранить смысловое воспоминание в ChromaDB.
- `memory_recall(query, n_results)`: Единый поиск по фактам, векторной памяти и документам.
- `memory_save_doc(folder, name, content)`: Создать структурированный markdown-документ.
- `memory_read_doc(folder, name)`: Прочитать документ.
- `memory_list_docs(folder)`: Список сохранённых документов.
- `memory_delete_doc(folder, name)`: Удалить документ.

### Причинность и обслуживание
- `memory_causal_log(id, text, layer, cause, effect, confidence)`: Записать причинный переход.
- `memory_causal_list(layer, session_id, limit)`: Список причинных записей по уровню абстракции.
- `memory_memory_context(project)`: Компактный срез активных убеждений и важных фактов.
- `memory_reinforce(key, layer)`: Вручную усилить громкость записи.
- `memory_sleep()`: Запустить цикл консолидации и затухания вручную.

## Ночная консолидация Dream

Движок `dream.py` запускается каждую ночь в 04:00 и выполняет три ключевые задачи:

1. **Степенное затухание громкости**:
   Громкость воспоминаний рассчитывается по формуле:
   $$V_{\text{eff}} = V_{\text{stored}} \cdot \left(1 + \frac{t_{\text{hours}}}{\tau}\right)^{-\alpha}$$
   Часто запрашиваемые данные остаются громкими, а невостребованный шум постепенно затихает до базового порога `0.01`. Данные не удаляются.
2. **Причинное обобщение**:
   Группирует наблюдения L0 в эпизоды L1, находит паттерны L2 и обновляет записи убеждений L3.
3. **Синхронизация идентичности**:
   Обновляет файлы в `~/.config/opencode/memory/notes/self/`, гарантируя быструю загрузку в хуках перед промптом.

## Удаление

Для удаления компонентов Crystallized:

```bash
./uninstall.sh            # Запросит подтверждение перед удалением данных
./uninstall.sh --keep-data # Удалит код и хуки, сохранив базу и заметки
./uninstall.sh --purge     # Полная очистка без подтверждений
```

`uninstall.sh` удаляет файлы строго по манифесту `.crystallized-manifest`, не затрагивая ваши личные скрипты в каталоге.

## Проблемы и решения

### Ошибка API HTTP 429
Убедитесь, что плагин `@thehugeman/opencode-anthropic-auth-community` добавлен в `opencode.json`:
```json
{
  "plugin": ["@thehugeman/opencode-anthropic-auth-community@latest"]
}
```

### Статус Memory MCP горит красным
Проверьте инициализацию базы SQLite:
```bash
cd ~/.config/opencode/memory
.venv/bin/python -c "import db; db.init_schema(); print('База данных готова')"
```

### Хуки наблюдателя не срабатывают
Проверьте регистрацию хуков в `~/.claude/settings.json`:
```bash
python3 -c "import json, os; print(json.load(open(os.path.expanduser('~/.claude/settings.json')))['hooks'].keys())"
```
При отсутствии запустите `./install.sh` для повторного объединения настроек.

### Токен не найден на Windows или macOS
1. Откройте Claude Desktop и убедитесь, что вход выполнен.
2. Полностью закройте Claude Desktop для сохранения файлов на диск.
3. Перезапустите `python3 auth/extract_token.py` (или `python auth\extract_token.py`).
