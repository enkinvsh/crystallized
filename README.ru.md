# Crystallized — постоянная память и идентичность для opencode

Crystallized — это MCP-сервер постоянной памяти для [opencode](https://opencode.ai), ИИ-агента для кодинга, который даёт агенту долговременную память между сессиями. Он объединяет три слоя хранения — факты в SQLite, семантический векторный поиск в ChromaDB и markdown-документы — под степенным затуханием памяти, так что важный контекст остаётся громким, старый шум стихает, и ничего не удаляется. Поверх памяти формируется эволюционирующая идентичность агента, а первопартийная авторизация Anthropic позволяет использовать ваш план Claude Max в opencode без детекции стороннего клиента.

**v2.0 работает без внешних сервисов.** Больше нет ни Redis, ни брокера, ни демона, за которым надо следить: всё хранилище — это одна база SQLite в режиме WAL плюс обычные файлы в вашем домашнем каталоге.

## Что даёт

- **Трёхслойная память**: SQLite для мгновенных фактов и убеждений, ChromaDB для семантического поиска по сессиям, файловая система для структурированных документов
- **Ноль внешних сервисов**: один файл SQLite в режиме WAL, никакого Redis, нечего держать запущенным
- **Автоинъекция контекста**: каждый промпт обогащается релевантным контекстом из прошлых разговоров
- **Причинное наблюдение**: результаты инструментов и транскрипты сессий разбираются на сигналы трения и консолидируются в убеждения
- **Идентичность агента**: убеждения, фокус и наблюдения начинают пустыми и кристаллизуются со временем через работу
- **Затухание памяти**: степенной закон, важное остаётся громким, старый шум стихает, ничего не удаляется
- **Первопартийная авторизация**: OAuth-токены прямо из Claude.app; ваш Max план, а не пул кредитов $200 для сторонних клиентов
- **Оркестрация Sisyphus**: oh-my-openagent с параллельными агентами, загрузкой скиллов и структурированным делегированием

## Требования

- **macOS** (основная) или Linux
- **Python 3.11+**, **git**, **curl**
- **[Claude.app](https://claude.ai/download)**: установлен и залогинен под вашим Max-аккаунтом (macOS, для извлечения первопартийных токенов)

Homebrew нужен только как запасной вариант, если не хватает вспомогательной утилиты вроде `unzip`. Больше он ни для чего не используется.

## Быстрый старт

```sh
# Сначала закройте Claude.app полностью (Cmd+Q)
git clone https://github.com/enkinvsh/crystallized.git
cd crystallized
./install.sh
opencode
```

Установщик сделает всё: Python-зависимости, opencode CLI, сервер памяти, схему SQLite, слияние конфигов, хуки, ночную задачу и извлечение авторизации.

Посмотреть весь план, ничего не меняя на машине:

```sh
./install.sh --dry-run
```

## Воспроизводимые установки

Репозиторий фиксирует `memory/uv.lock`, поэтому каждая установка резолвится в одни и те же версии Python-зависимостей. Чтобы обновить lock-файл после правки `memory/pyproject.toml`, выполните `uv lock` внутри каталога `memory/` и закоммитьте обновлённый lock-файл.

## Что делает install.sh

1. Проверяет зависимости: `git`, `python3` 3.11+ и `curl`.
2. Устанавливает менеджер пакетов `uv` от astral.sh, если его нет.
3. Устанавливает CLI `opencode` из релизов GitHub, если его ещё нет в PATH.
4. Разворачивает модули сервера памяти в `~/.config/opencode/memory/` и записывает список скопированного в `.crystallized-manifest`.
5. Устанавливает Python-зависимости в `~/.config/opencode/memory/.venv` через `uv sync --frozen`.
6. Инициализирует схему SQLite в `~/.config/opencode/memory/memory.db` (режим WAL) командой `python -c "import db; db.init_schema()"` и печатает получившийся `PRAGMA user_version`.
7. Создаёт шаблоны идентичности (beliefs, focus, observations, journal) в `~/.config/opencode/memory/notes/`.
8. Сливает `~/.config/opencode/opencode.json` с записью MCP памяти и записью плагина. Существующий файл сначала бэкапится, а записи, которые вы уже определили, никогда не перезаписываются.
9. Сливает хуки из `config/claude-settings.json` в `~/.claude/settings.json`, создавая файл, если его нет. Трогается только ветка `hooks`: все остальные ключи и все чужие хуки сохраняются, а повторный запуск установщика не плодит дубликаты.
10. Ставит ночную задачу консолидации: агент launchd в `~/Library/LaunchAgents/com.crystallized.dream.plist` на macOS или помеченную строку crontab на Linux. Запускается ежедневно в 04:00, лог пишет в `~/.config/opencode/memory/dream.log`.
11. На macOS извлекает OAuth-токены Claude.app через Keychain и записывает их в `~/.local/share/opencode/auth.json`.

### Флаги установщика

| Флаг | Действие |
|---|---|
| `--dry-run` | Печатает все действия, ничего не меняя на диске |
| `--no-hooks` | Пропускает регистрацию хуков в `~/.claude/settings.json` |
| `--no-daemon` | Пропускает ночную задачу консолидации (launchd / cron) |
| `--offline` | Никогда не лезет в сеть: вместо загрузки завершается ошибкой |
| `--help`, `-h` | Показывает справку и выходит |

### Какие хуки регистрирует установщик

| Событие | Команда | Назначение |
|---|---|---|
| `UserPromptSubmit` | `memory-inject.py` | Подставляет в промпт релевантную память |
| `UserPromptSubmit` | `own-voice.py` | Подставляет эволюционирующую идентичность агента |
| `PostToolUse` | `observer.py --post-tool` | Ловит сигналы трения в результатах инструментов |
| `Stop` | `observer.py --session-end` | Разбирает завершённый транскрипт на наблюдения |

## Что install.sh НЕ делает

- Не устанавливает, не запускает и не требует Redis. В v2.0 он убран полностью.
- Не изменяет Claude.app и его файлы.
- Не трогает ваши rc-файлы оболочки. Если после установки `opencode` не оказался в PATH, установщик печатает однострочную подсказку `export PATH=...`, чтобы вы добавили её сами.
- Не отправляет данные. Никакой телеметрии, аналитики или удалённого логирования.
- Не работает на Windows. WSL не тестировался.
- Не находит Claude.app вне `/Applications/Claude.app`. Если Claude установлен в нестандартное место, запустите `python3 auth/extract_token.py` вручную.

## Оговорки

- При извлечении авторизации Keychain может запросить пароль вашей учётки macOS. Выберите "Always Allow", чтобы избежать повторных запросов.
- На Linux шаг автоматической авторизации пропускается. Нужно извлечь токены с мака, использовать API-ключ напрямую или принять маршрутизацию через сторонний пул кредитов.
- Установщик рассчитан на однопользовательский Mac. Многопользовательские общие установки не поддерживаются.
- Холодный старт ChromaDB может занять от 10 до 30 секунд при первом MCP-вызове, пока скачивается модель sentence-transformer.
- Каталог памяти общий со всем, что вы там держите. `uninstall.sh` удаляет только то, что перечислено в манифесте установки, поэтому ваши собственные скрипты в этой папке остаются нетронутыми.

## Удаление

```sh
./uninstall.sh            # спросит перед удалением данных памяти
./uninstall.sh --keep-data
./uninstall.sh --purge
./uninstall.sh --dry-run
```

`uninstall.sh` выгружает и удаляет агент launchd (или убирает строку cron), снимает регистрацию хуков Crystallized в `~/.claude/settings.json`, не трогая чужие хуки, убирает запись MCP памяти из `opencode.json`, удаляет развёрнутые модули и `.venv`, и — только с вашего согласия — удаляет `memory.db` вместе с файлами `-wal` и `-shm`, а также `notes/`, `chroma_db/`, `identity.json` и остатки `vault/` от установок до 2.0.

## Необязательные переменные окружения времени выполнения

Все переменные окружения времени выполнения необязательны. По умолчанию используются те пути, которые прописывает установщик.

| Переменная | Назначение |
|---|---|
| `OPENCODE_MEMORY_DB` | Путь к базе SQLite с памятью. |
| `OPENCODE_MEMORY_NOTES_DIR` | Каталог заметок для сохранённых документов и файлов идентичности. |
| `OPENCODE_MEMORY_CHROMA_DIR` | Каталог постоянного хранения ChromaDB. |
| `OPENCODE_MEMORY_IDENTITY` | Путь к выгруженной карте громкостей. |
| `OPENCODE_MEMORY_SOCKET` | Unix-сокет, через который хуки достают прогретый энкодер. |
| `OPENCODE_MEMORY_DISABLE_CHROMA_API` | Значение `0` включает обратно внутрипроцессный API ChromaDB. По умолчанию выключен. |
| `CRYSTALLIZED_OBSERVER_BUDGET_MS` | Дедлайн хука-наблюдателя в миллисекундах. |

## Обновление с v1.x

В v2.0 слой фактов на Redis заменён на SQLite. Заберите новый код и перезапустите установщик:

```sh
git pull
./install.sh
```

Установщик делает резервные копии `opencode.json` и `~/.claude/settings.json` перед слиянием, так что ничего из вашей настройки не потеряется. После обновления Redis можно остановить, если вы поднимали его только ради Crystallized:

```sh
brew services stop redis     # macOS
sudo systemctl stop redis    # Linux
```

Переменные `REDIS_URL`, `REDIS_HOST`, `REDIS_PORT` и `REDIS_DB` больше нигде не читаются.

Если что-то сломалось, запустите `./uninstall.sh --keep-data`, затем снова запустите `./install.sh`.

Полные заметки о релизе смотрите в [CHANGELOG.md](CHANGELOG.md).

## Почему opencode помечает сторонние клиенты (и как Crystallized это исправляет)

Anthropic определяет сторонние клиенты и направляет их API-запросы в отдельный пул кредитов ($200) вместо вашей Max-подписки. Коммьюнити-плагины авторизации получают OAuth-токены со сторонним `client_id`, поэтому каждый запрос помечается.

Crystallized извлекает токены напрямую из Claude.app. Они несут собственный `client_id` Claude, поэтому Anthropic считает ваши сессии opencode первопартийными. Лимиты Max-плана работают штатно.

## Как работает

### Трёхслойная архитектура памяти (SQLite + ChromaDB + файловая система)

`memory-inject.py` запускается как хук перед каждым промптом. Ищет релевантный контекст по слоям и вставляет его:

| Слой | Движок | Назначение |
|---|---|---|
| Факты и убеждения | SQLite (WAL) | Имена, решения, предпочтения, мгновенный key/value |
| Семантика | ChromaDB | Векторный поиск по всему, что агент когда-либо запоминал |
| Документы | Файловая система | Архитектурные заметки, чеклисты, саммари сессий |

Затухание работает по степенному закону. Воспоминания никогда не удаляются, они становятся тише.

### Наблюдение и ночная консолидация

`observer.py` запускается на событиях `PostToolUse` и `Stop`. Он прогоняет регулярки по выводу инструментов и по завершённым транскриптам и пишет сырые строки `layer=0` в `causal_memories`. Он намеренно дешёвый: у него бюджет в миллисекундах, он всегда завершается кодом `0` и никогда не печатает на пути инструмента, так что хук физически не может оборвать или затормозить ход агента.

Дорогая половина работы идёт, пока вы не работаете. Ночная задача поднимает сырые наблюдения вверх по уровням — сырой сигнал, эпизод, паттерн, принцип — и разрешает противоречия в `belief_state`, би-темпоральной таблице, где на пару «субъект + предикат» активным может быть ровно одно убеждение. Вытесненные убеждения помечаются, а не удаляются, поэтому история того, что агент думал раньше, остаётся доступной для запросов.

### Идентичность

`own-voice.py` инъектирует эволюционирующую идентичность агента в каждый промпт. Убеждения, фокус и наблюдения начинают как пустые файлы и заполняются по мере работы. Личность заработана опытом, а не задана конфигом.

### Авторизация

`auth/extract_token.py` расшифровывает safeStorage Claude.app (Electron, AES-128-CBC через macOS Keychain), извлекает OAuth-токены и записывает их в `auth.json` opencode. Обновление токена opencode делает сам, никакой auth-плагин при работе не нужен.

## Архитектура

```
~/.config/opencode/
├── opencode.json              # MCP-серверы, плагины
└── memory/
    ├── server.py              # MCP сервер памяти (SQLite + ChromaDB + fs)
    ├── db.py                  # Слой хранения SQLite, миграции схемы
    ├── volume.py              # Математика степенного затухания
    ├── observer.py            # Хук: захват сигналов на PostToolUse / Stop
    ├── patterns.py            # Регулярки, которые применяет наблюдатель
    ├── dream.py               # Ночной проход консолидации
    ├── memory-inject.py       # Хук: инъекция контекста
    ├── own-voice.py           # Хук: инъекция идентичности
    ├── pyproject.toml         # Python-зависимости
    ├── .crystallized-manifest # Что развернул install.sh (читает uninstall.sh)
    ├── memory.db              # Хранилище SQLite, режим WAL (генерируется)
    ├── chroma_db/             # Векторная БД (генерируется)
    ├── notes/self/            # Идентичность агента (генерируется)
    │   ├── beliefs.md
    │   ├── focus.md
    │   └── observations.md
    ├── identity.json          # Карта громкости (генерируется)
    └── dream.log              # Вывод ночной задачи (генерируется)

~/.claude/
└── settings.json              # Регистрация хуков (сливается, не перезаписывается)

~/Library/LaunchAgents/
└── com.crystallized.dream.plist   # Ночная консолидация (macOS)

~/.local/share/opencode/
└── auth.json                  # OAuth-токены (из Claude.app)
```

## Проблемы и решения

**Ошибка "Third-party apps"**, неправильный токен. Закройте Claude.app, затем:
```sh
python3 auth/extract_token.py
```
Если несколько workspace, попробуйте каждый индекс.

**Memory MCP красный**, проверьте, что путь к `uv` в `opencode.json` абсолютный. Установщик прописывает его именно так, но ручные правки могут сломать. Затем проверьте, что хранилище открывается:

```sh
cd ~/.config/opencode/memory && .venv/bin/python -c "import db; db.init_schema(); print('ok')"
```

**Хуки не срабатывают**, убедитесь, что они зарегистрированы и что путь к интерпретатору существует:

```sh
python3 -c "import json;print(json.load(open('$HOME/.claude/settings.json'))['hooks'].keys())"
ls ~/.config/opencode/memory/.venv/bin/python
```

Перезапустите `./install.sh`, чтобы зарегистрировать заново: дубликатов он не создаст.

**Ночная задача не запускается**, проверьте, что она загружена, и прочитайте лог:

```sh
launchctl list | grep crystallized      # macOS
crontab -l | grep crystallized-dream    # Linux
tail ~/.config/opencode/memory/dream.log
```

**Keychain access denied**, нужен терминал с GUI, не чистый SSH. Или разблокируйте сначала:
```sh
security unlock-keychain ~/Library/Keychains/login.keychain-db
```

**Linux**, извлечение авторизации только для macOS (Claude.app). Перенесите токены с мака, используйте API-ключ напрямую или примите маршрутизацию через сторонний пул.

## FAQ

**Забывает ли opencode контекст между сессиями?**
По умолчанию да — каждая сессия начинается с нуля. Crystallized это исправляет: он сохраняет факты, семантические воспоминания и документы на диск и заново вставляет релевантные в каждый промпт, так что агент несёт долговременную память между сессиями.

**Заработает ли это с другими MCP-клиентами или только с opencode?**
Сервер памяти — стандартный сервер [Model Context Protocol](https://modelcontextprotocol.io), так что подключиться может любой MCP-клиент. Установщик, pre-prompt хуки и инъекция идентичности заточены под opencode, поэтому другие клиенты получат инструменты памяти, но без автоматической инъекции контекста.

**Уходят ли мои данные куда-либо?**
Нет. Память полностью живёт на вашей машине — один файл SQLite, ChromaDB и markdown-файлы на локальном диске. Ничто не слушает сетевой порт. Никакой телеметрии, аналитики и удалённого логирования. Полная модель угроз — в [SECURITY.md](SECURITY.md).

**Нужен ли ещё Redis?**
Нет. В v2.0 он убран. Факты, убеждения, громкости и журнал событий лежат в одной базе SQLite в режиме WAL, так что нет сервиса, который надо ставить, запускать и поддерживать живым.

**Почему Anthropic направляет opencode в пул кредитов $200?**
Anthropic определяет сторонние клиенты по их OAuth `client_id` и списывает их в отдельный пул кредитов вместо вашей подписки. Crystallized извлекает первопартийные токены из Claude.app, поэтому opencode считается первопартийным и лимиты вашего плана Claude Max работают штатно.

**Растёт ли память бесконечно?**
Нет. Память затухает по степенному закону: записи становятся тише со временем, если их не подкреплять. Ничего никогда не удаляется — старый шум просто перестаёт всплывать, а важный контекст остаётся громким.

**Есть ли поддержка Windows?**
Нет. Crystallized нацелен на macOS (основная) и Linux. WSL не тестировался, а извлечение авторизации зависит от macOS Keychain.
