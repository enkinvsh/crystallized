# <img src="docs/icons/brain.svg" width="28" alt="" /> Crystallized

У каждой языковой модели есть врожденный дефект: она просыпается без прошлого.

Ты можешь провести с ней десять часов, настроить идеальный пайплайн, объяснить архитектуру, пять раз одернуть за дурацкие библиотеки и договориться о стиле кода. Но стоит закрыть терминал и открыть новую сессию — перед тобой снова чистый лист. Тот же восторженный джуниор, который опять предлагает `var` вместо `const`, лезет руками в неприкосновенный конфиг и ничего не знает о твоих нервах.

Обычно эту проблему пытаются залить векторными базами и RAG. Но поиск по близости слов в кодинге быстро превращается в кашу: модель вытаскивает старые опровергнутые гипотезы трехмесячной давности вперемешку со свежими правилами и окончательно сходит с ума.

**Crystallized устроен иначе.** Это не склад переписок, а модель долговременной памяти, где опыт кристаллизуется в принципы, а старое знание уступает место новому.

## <img src="docs/icons/workflow.svg" width="22" alt="" /> Анатомия памяти: от замечания к инстинкту

Человеческий мозг не помнит каждый байт прожитого дня. Он запоминает точки напряжения, переваривает их во сне и превращает в автоматические привычки. 

В Crystallized этот путь разбит на четыре слоя:

```
+-------------------------------------------------------------------------+
| L0: СЫРОЙ СЛЕД (Наблюдатель / Observer)                                 |
| Ты отменил команду, откатил диф или написал «не трогай этот файл».      |
| Перехватчик за 0.05мс фиксирует причину и следствие прямо в SQLite WAL.  |
+------------------------------------+------------------------------------+
                                     |
                                     v
+-------------------------------------------------------------------------+
| L1: ЭПИЗОД (Session End)                                                |
| Сессия завершена. Десятки микро-правок склеиваются в связную историю:   |
| «Попытался сделать X -> пользователь отверг из-за Y -> сработал Z».     |
+------------------------------------+------------------------------------+
                                     |
                                     v
+-------------------------------------------------------------------------+
| L2: ПАТТЕРН (Dream Engine @ 04:00)                                      |
| Ночной процесс собирает повторяющиеся эпизоды за неделю.                |
| Случайный шум отсеивается, частые грабли становятся паттерном.          |
+------------------------------------+------------------------------------+
                                     |
                                     v
+-------------------------------------------------------------------------+
| L3: АКСИОМА (Belief State)                                              |
| Итоговое неизменяемое правило поведения.                                |
| На старте сессии оно уже лежит в контексте агента до первого вопроса.   |
+-------------------------------------------------------------------------+
```

### Главный принцип: Память — это не поиск, а состояние

- **Вытеснение вместо накопления (Supersession)**: Если месяц назад ты просил писать тесты на Jest, а вчера перешел на Vitest — старое убеждение не висит рядом, а явно помечается как `superseded`. Модель физически не может получить два конфликтующих правила.
- **Честное затухание (Power-law Decay)**: То, с чем ты работаешь каждый день, звучит громко. Редкие временные мелочи тихо угасают по степенному закону.
- **Никаких тяжелых сервисов**: Никакого Redis, фоновых очередей на Node.js или облачных векторных сервисов. Вся система — это один локальный файл `memory.db` (SQLite в режиме WAL) и текстовые markdown-документы.

## <img src="docs/icons/flash.svg" width="22" alt="" /> Запуск

```bash
git clone https://github.com/enkinvsh/crystallized.git
cd crystallized
./install.sh
```

Скрипт разворачивает изолированное Python-окружение через `uv`, инициализирует базу данных, прописывает хуки авто-инъекции в `~/.claude/settings.json` и настраивает ночную консолидацию через системный демон.

## <img src="docs/icons/key.svg" width="22" alt="" /> Подписка Claude Pro / Max без переплат

Если у тебя уже есть подписка в веб-версии или приложении Claude, тебе не нужно покупать отдельный API-ключ с поминутной оплатой.

Crystallized умеет безопасно доставать авторизацию прямо из официального клиента Claude Desktop:

- **macOS**: `python3 auth/extract_token.py` (читает ключ из системного Keychain и расшифровывает локальную сессию).
- **Windows**: `python auth\extract_token.py` (расшифровывает мастер-ключ через Windows DPAPI).

Токены остаются строго на твоем диске в `~/.local/share/opencode/auth.json`. Подробнее: [docs/AUTHENTICATION.md](docs/AUTHENTICATION.md).

## <img src="docs/icons/tools.svg" width="22" alt="" /> Инструменты под капотом

Внутри сессии агент управляет своей памятью через набор нативных MCP-инструментов:

- `memory_belief_assert`: зафиксировать жесткое правило (с автоматическим вытеснением старого).
- `memory_causal_log`: сохранить урок или причинно-следственную цепочку.
- `memory_save_fact` / `memory_get_fact`: быстрые неизменяемые факты (порты, хосты, стеки).
- `memory_save_doc` / `memory_read_doc`: полноценные архитектурные документы и манифесты.
- `memory_recall`: гибридный поиск по смыслу и ключевым словам, когда нужно поднять контекст давней задачи.

## <img src="docs/icons/laptop.svg" width="22" alt="" /> Каталог расширений

Память дает агенту контекст, но ему нужны и руки для работы. В директории `config/mcp/` лежат готовые модульные конфиги:

- **Символьная навигация (`serena`)**: понимание классов, методов и AST-дерева без прочтения гигабайтов кода.
- **Граф кодовой базы (`codebase-memory`)**: связи между модулями, импорты и пути вызовов.
- **Браузерная автоматизация (`playwright`)**: управление реальным Chrome, тестирование и снятие скриншотов.
- **Мобильный контур (`flutter-dev`)**: работа с реальным Android-девайсом через ADB и хот-релоад.
- **Поисковая аналитика (`seo-analytics`)**: связка Google Search Console и Яндекс.Метрики.

Инструкции по подключению: [docs/MCP_CATALOG.md](docs/MCP_CATALOG.md).
